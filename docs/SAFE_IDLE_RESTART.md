# Mac 空閒重啟整合

桌面版提供本機 Unix socket `~/Library/Application Support/AI Trinity Desk/memory-guard.sock` 給記憶體小幫手。只有 macOS 桌面版會啟用；網頁服務不受影響。

## 允許重啟的條件

1. 所有 CLI 工作階段均已停止，包括隱藏的 Agent。CLI 開著但等待輸入時，仍無法確認內部或背景任務，因此保守延後。
2. 沒有討論、安裝、翻譯、尚未完成的操作或儲存。
3. 沒有未送出的討論主題／補充問題、尚未完成的回覆、儲存失敗，亦未開啟設定、市場、模型面板。
4. App 連續空閒至少 15 分鐘，Mac 也至少 15 分鐘未有人操作。開機、喚醒、新輸入、新操作與忙碌狀態會重新計時。
5. 重啟前重新向畫面查詢；沒有回應就拒絕。畫面會同時檢查實際輸入值，避免 React 狀態同步延遲遺漏剛輸入的草稿。
6. 確認後先禁止新操作、暫停畫面輸入，完成儲存並再次檢查工作／操作狀態，才要求正常退出及重新開啟。檢查或儲存逾時會恢復輸入，沒有強制關閉。

## 通訊與保護

連線檔權限 `0600`；父目錄必須屬於當前使用者，且不能允許群組或其他使用者寫入。不開 TCP 埠、不傳送對話／草稿內容。重啟要求必須符合目前 PID 與每次啟動新產生的識別碼；舊狀態不可用於新 App。訊息長度及連線等待皆有上限。既有普通檔案不會被覆寫。

- `{"op":"status"}`：回傳協定版本、PID、識別碼、工作狀態、原因、App／Mac 空閒秒數與查詢時間。
- `{"op":"restart","pid":123,"instance":"目前識別碼"}`：重新執行完整檢查，不接受較短的空閒時間或任意指令。

記憶體小幫手在排程時間記住當時開啟的 App 與 PID；忙碌每分鐘重查，最多 4 小時。狀態缺漏／過期或 App 換了工作階段就跳過。發出重啟要求前先消耗該次工作，避免回應遺失導致重複重啟。

## 驗證

`tests/idle-maintenance.test.ts` 驗證互斥、等待時間、待完成操作、未知狀態、連線權限與識別碼。`tests/maintenance-e2e.mjs` 使用隔離的測試設定與模擬 CLI，驗證隱藏工作、草稿、設定面板、剛開始的新工作，以及重啟準備後不再接受新任務。成功路徑只替測試程序調整時鐘並攔截重新啟動／退出要求；正式程式沒有縮短 15 分鐘的測試環境開關。
